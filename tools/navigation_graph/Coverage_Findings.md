## 2. Clear-History Edges (24 total)

These edges set `clear_history=True` on the `Destination`, which wipes the Controller's back stack. Pressing "Back" after these transitions goes directly to `MainMenuView` instead of the previous View.

### Intentional Security Resets

These clear the back stack to prevent navigating back to sensitive seed material.

| Source | Target | Why |
|--------|--------|-----|
| SeedFinalizeView | SeedOptionsView | After finalizing a seed, can't go back to re-edit |
| SeedReviewPassphraseView | SeedOptionsView | After confirming passphrase, can't go back |
| SeedDiscardView | MainMenuView | After discarding, seed data is gone |
| SeedWordsBackupTestSuccessView | SeedOptionsView | After passing backup test |
| SeedTranscribeSeedQRConfirmQRPromptView | SeedOptionsView | After transcribe confirmation |

## 5. Key Observations

1. **52.6% coverage** — 110 of 209 unique navigation pairs are exercised by FlowTests.

2. **Entire backup verification flow is untested** — The 16-edge `SeedWordsWarningView → SeedWordsView → SeedWordsBackupTestPromptView → SeedWordsBackupTestView → SeedWordsBackupTestSuccessView` chain has zero FlowTest coverage. This is the largest contiguous uncovered subgraph.

3. **All entropy tool flows are untested** — Dice, image, and coin-flip entropy flows have no FlowTests. 13 edges total.

4. **BIP-85 child key derivation is untested** — The `SeedBIP85SelectNumWordsView → SeedBIP85SelectChildIndexView → SeedBIP85InvalidChildIndexView` flow is missing FlowTests. 4 edges.

5. **PSBT error paths are untested** — `PSBTNoChangeWarningView`, `PSBTUnsupportedScriptTypeWarningView`, `PSBTAddressVerificationFailedView`, and `PSBTSigningErrorView → MainMenuView` lack coverage.

6. **ScanView sub-class mismatch** — The static graph has edges from `ScanView` but FlowTests use `ScanSeedQRView`, `ScanAddressView`, `ScanWalletDescriptorView` (subclasses). This causes 6 edges to appear "uncovered" and 4 to appear "tested-only". The underlying transitions ARE tested, just under different class names.

7. **24 clear_history edges** are architectural guard rails — they intentionally prevent back-navigation to sensitive screens (seed material, signed PSBTs, entropy sources). All are by design.

8. **3 dynamic edges** in `SettingsEntryUpdateSelectionView` cannot be resolved statically. They use `self.blocking_view` / `self.unblocking_view` which are set at runtime by the caller. FlowTests for `RemoveMicroSDWarningView` do exercise these paths, but matching requires manual verification.
